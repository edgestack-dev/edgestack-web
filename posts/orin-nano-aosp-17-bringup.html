Bringing Up AOSP 17 on NVIDIA Jetson Orin Nano

Published: August 2026 • Architecture & System Integration

Targeting newer Android Open Source Project releases on edge AI hardware platforms like the Jetson Orin Nano requires carefully bridging kernel configurations, device tree blobs (DTB), and custom hardware abstraction layers (HALs) via crosvm and KVM virtualization.

1. Host Differences (Orin vs. RPi5)

Running Cuttlefish targets on embedded ARM64 hosts presents unique platform constraints compared to standard reference boards like the Raspberry Pi 5:

Aspect Raspberry Pi 5 NVIDIA Orin Nano
OS / Environment Debian Bookworm / Ubuntu 24.04 L4T Ubuntu 22.04 (JetPack)
Kernel Base 6.x mainline 5.15.148-tegra
RAM Allocation 4GB total (1GB assigned to VM) 8GB total (2GB assigned to VM)
vhost_vsock Available via standard modprobe Requires manual build from L4T kernel source
virglrenderer System package (>=1.0) Must build from source (L4T ships legacy 0.9.1)

2. Additional Build Dependencies

Ensure the host has the required toolchains and graphics development packages installed:

sudo apt install -y \
    clang \
    libclang-dev \
    libepoxy-dev \
    meson \
    ninja-build \
    curl

3. Build virglrenderer from Source

To satisfy modern graphics virtualization requirements, build the latest virglrenderer package directly:

cd ~/work
git clone https://gitlab.freedesktop.org/virgl/virglrenderer.git
cd virglrenderer
meson setup builddir -Dprefix=/usr/local
ninja -C builddir
sudo ninja -C builddir install
sudo ldconfig

4. Build crosvm

Fetch and compile crosvm with support for virtualized graphics rendering:

cd ~/work
git clone https://chromium.googlesource.com/crosvm/crosvm
cd crosvm
git submodule update --init
cargo build --release --features "virgl_renderer"

5. Patch vbmeta (Disable AVB Verification)

Bypass Android Verified Boot constraints on target disk images:

cd ~/work/aosp/images
printf '\x00\x00\x00\x03' | dd of=vbmeta.img seek=120 bs=1 count=4 conv=notrunc
printf '\x00\x00\x00\x03' | dd of=vbmeta_system.img seek=120 bs=1 count=4 conv=notrunc

6. Patch Vendor Image (Disable Encryption)

Modify vendor flags to suppress file-based and metadata encryption checks unsupported in light container/VM boundaries:

sudo perl -pi -e '
    s/metadata_encryption/xetadata_encryption/g;
    s/fileencryption/xileencryption/g;
    s/wrappedkey/xrappedkey/g;
    s/keydirectory/xeydirectory/g
' /tmp/vendor_a.img

7. Execution & Boot Command

Launch the virtual machine instance using the compiled binary and configured composite disk layout:

sudo ../crosvm/target/release/crosvm run \
    -m 1024 --cpus 2 --disable-sandbox \
    --cid 3 \
    --serial type=stdout,stdin=true \
    -p "console=ttyAMA0 loglevel=0 androidboot.hardware=cutf_cvm ..." \
    --block path=composite.img \
    --initrd merged_ramdisk.img \
    boot_unpacked/kernel

8. ADB Access via vsock

Establish direct debugging connectivity using virtual socket interfaces:

adb connect vsock:3
adb shell

9. Display Output via Weston

Configure the DRM compositor runtime backend to render UI frames locally:

export XDG_RUNTIME_DIR=/tmp/weston-run
mkdir -p $XDG_RUNTIME_DIR && chmod 700 $XDG_RUNTIME_DIR
weston --backend=drm-backend.so --current-mode 2>&1 &

10. Troubleshooting Highlights

  • vhost_vsock missing: Compile missing modules using the L4T kernel source tree with CONFIG_LOCALVERSION="-tegra".
  • SurfaceFlinger SIGABRT: Force ANGLE backend options (egl=angle) or integrate the gfxstream_backend library.
  • Persistent Disk Conflicts: Clean and recreate raw GPT persistent disk slices following every automated assemble_cvd pass.

11. Full run_cvd Launch Sequence

For automated orchestration, start the complete Cuttlefish runtime loop:

cd ~/work/aosp_imgs
ulimit -n 65536
ANDROID_HOST_OUT=$PWD HOME=$PWD nohup ./bin/run_cvd > /tmp/run_cvd_out.log 2>&1 &
